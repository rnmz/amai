# Справочник синтаксиса (для авторов)

### Базовое форматирование

* `**жирный текст**`
* `*курсив*`
* `~~зачёркнутый~~`
* `==выделенный маркером текст==` — зелёный маркер
* `\- выделенный маркером текст -\` — то же самое, но красный

Оба маркера — не часть стандартного Markdown, реализованы отдельными расширениями в `marked-render.ts` (`extension mark` / `markRed`). Внутри поддерживается вложенное форматирование (`==**жирный внутри маркера**==` работает, `\- **жирный внутри** -\` тоже).

В отличие от `==...==`, красный маркер спокойно допускает обычные дефисы внутри текста — `\- рост на 5-10% за квартал -\` сработает корректно, потому что открывающая/закрывающая последовательности (`\-` и `-\`) достаточно специфичны и с одиночным дефисом не путаются. Пробелы вокруг текста опциональны (`\-текст-\` тоже работает), но для читаемости исходника рекомендуется писать с пробелами.

### Заголовки

```markdown
# H1
## H2
### H3
#### H4
##### H5
###### H6

```

Каждый заголовок автоматически получает `id` (slug) и иконку-якорь `#`, которая появляется при наведении — можно скопировать прямую ссылку на раздел.

#### Центрирование

Если перед решётками поставить `$`, заголовок будет выровнен по центру вместо стандартного левого края:

```markdown
# Обычный заголовок — слева
$## Центрированный заголовок второго уровня

```

Работает для всех уровней (`$#`…`$######`), поддерживает вложенное форматирование (`**жирный**`, `код` и т.д.) точно так же, как обычные заголовки.

Единственное отличие в разметке — иконка-якорь у центрированных заголовков стоит перед текстом инлайном, а не абсолютным позиционированием слева (при центрировании текста фиксированный отступ от левого края съезжал бы непредсказуемо в зависимости от длины заголовка).

### Таблицы

```markdown
| Колонка | По центру | По правому краю |
|:---|:---:|---:|
| a | b | c |

```

* Колонки, выровненные по правому краю, автоматически получают моноширинный шрифт с табличными цифрами (`font-variant-numeric: tabular-nums`) — удобно для финансовых данных.
* **Цветовая разметка положительных/отрицательных/нейтральных значений** — короткий синтаксис `[pos=...]` / `[neg=...]` / `[neut=...]`:

```markdown
| Актив | Доходность |
|:---|---:|
| Акции | [pos=+18.4%] |
| Облигации | [neg=−1.2%] |
| Депозит | [neut=0.0%] |

```

Работает не только в таблицах — в любом инлайн-контексте (параграфы, списки). Значение внутри `[]` не может содержать символ `]`.

**Горизонтальный скролл на мобильных:** широкая таблица не ломает вёрстку и не сжимает колонки — вместо этого появляется горизонтальный скролл внутри самой таблицы. Реализовано через `renderer.table` в `marked-render.ts`, который оборачивает вывод в `<div class="table-wrapper">`, плюс `white-space: nowrap` на `th`/`td` в CSS.

Из-за `nowrap` длинный текстовый контент в ячейке (не только числа) тоже не переносится — для таблиц с короткими значениями (цифры, категории) это то поведение, которое нужно; если понадобится таблица с многострочным текстовым описанием в конкретной колонке, для неё стоит точечно переопределить `white-space: normal`.

### Формулы (KaTeX)

**Инлайн** — рекомендуемый способ через `\(...\)`:

```markdown
Формула \(E = mc^2\) прямо в тексте.

```

**Блочная** — через `$$...$$`:

```markdown
$$
NPV = \sum_{t=1}^{n} \frac{CF_t}{(1+r)^t} - C_0
$$

```

Одиночный `$...$` тоже поддержан (`katexDollarExtension`) с эвристикой: если сразу после `$` идёт цифра — считается денежной суммой (`$100`), а не формулой, и не трогается. Это разруливает большинство реальных кейсов (`$CF_t$`, `$x$` — формулы; `$100`, `$1,234` — деньги), но эвристика не стопроцентная (например, формула `$2x+1$`, начинающаяся с цифры, не распознается).

Рекомендуется по умолчанию писать через `\(...\)` — там таких ограничений нет; `$...$` — доступный, но не основной способ.

### Диаграммы (Chart.js)

Блок с языком `chart` (или `chartjs`) и JSON-конфигом Chart.js внутри:

```markdown
​```chart
{
  "type": "bar",
  "data": {
    "labels": ["Jan", "Feb", "Mar"],
    "datasets": [{ "label": "Sales", "data": [10, 20, 15] }]
  }
}
​```

```

Конфиг — это ровно объект `ChartConfiguration` из Chart.js (`type` / `data` / `options`), никакой собственной обёртки нет: всё, что валидно в самом Chart.js, валидно и здесь. Работают все стандартные типы — `bar`, `line`, `pie`, `doughnut`, `radar`, `polarArea`, `scatter`, `bubble` — а также любые их комбинации через `options` (stacked-бары, смешанные датасеты и т.д.), поскольку подключён `chart.js/auto` со всеми зарегистрированными контроллерами. Подробный разбор каждого типа с примерами — в отдельной статье «Все типы графиков Chart.js».

**Позиционирование** — вторым параметром через `:` в языке блока:

```markdown
​```chart:left    → чарт слева, текст обтекает справа
​```chart:right   → чарт справа, текст обтекает слева
​```chart:float   → узкое обтекание (280px, «журнальный» стиль для мелких иллюстраций внутри абзаца)
​```chart:full    → на всю ширину, разрывает колонку текста
​```chart         → без модификатора — блочный элемент на всю ширину без обтекания
```

```markdown
Текст перед графиком...

​```chart:right
{ "type": "line", "data": { ... } }
​```

Текст после — обтекает график автоматически за счёт float, без ручных `<div>`-обёрток.

```

**Ограничения формата:**

* Конфиг — чистый JSON, поэтому **функции и колбэки не поддерживаются** (`options.plugins.tooltip.callbacks`, кастомные форматтеры на `scales.ticks.callback` и т.п.) — JSON не умеет сериализовать функции. Доступна только декларативная часть конфига Chart.js.
* Если JSON невалиден или Chart.js не смог инициализироваться — вместо графика показывается блок с классом `chart-error` и текстом «Invalid chart config», сам пост при этом не ломается.
* Несколько `chart:left`/`chart:right` подряд без текста между ними встанут в ряд друг с другом (за счёт float), а не друг под другом — это ожидаемое поведение float, но не всегда очевидное для автора поста.
* `chart:full` делает `clear: both`, поэтому корректно «сбрасывает» предыдущие float-графики перед собой — специально следить за этим при написании поста не нужно.
* В админке (превью поста) графики перерисовываются с дебаунсом при каждом изменении текста, но только пока открыта вкладка «Превью» — если писать длинный пост с большим количеством графиков, возможна небольшая задержка перед их появлением после переключения в превью (это нормально, не баг).

### Сноски

```markdown
Текст со сноской[^label].

[^label]: Расшифровка сноски.

```

* Метка (`label`) — произвольная, главное уникальная в пределах документа.
* Определение может стоять в любом месте документа, порядковый номер присваивается по порядку появления ссылки в тексте.
* Если сослались на метку без определения — `[^label]` останется как обычный текст.
* Определение без ссылки в тексте — молча игнорируется.

### Дисклеймер

Три равнозначных способа — выбирайте по удобству.

**1. Блочный, через fence** (рекомендуемый способ для отдельного абзаца-предупреждения):

```markdown
​```disclaimer
Текст дисклеймера.
​```

```

**2. Инлайн, прямо в предложении** — тот же префикс, но внутри одинарных бэктиков:

```markdown
Обычный текст, а тут `disclaimer важное предупреждение` прямо посреди абзаца.

```

Отличается от обычного инлайн-кода только префиксом `disclaimer ` (с пробелом после слова) — `` `disclaimer()` `` как вызов функции этот префикс не заденет, пробела там нет.

**3. Сырой HTML** — как и раньше, если нужен полный контроль над версткой блока:

```html
<div class="disclaimer">
Текст дисклеймера.
</div>

```

Оба новых варианта (fence и инлайн) не парсят markdown внутри — текст экранируется и выводится как есть, аналогично тому, как `marked` не трогает содержимое HTML-блока в третьем варианте. Если внутри дисклеймера нужны `**жирный**`, ссылки и т.д. — пока только через сырой HTML.

### Произвольный HTML

Поскольку публиковать посты может только админ, `marked` не санитизирует HTML — можно вставлять любые `<div>`, инлайн-стили и т.д. прямо в `.md`-файл, когда возможностей Markdown не хватает.

## Известные ограничения

* **Формулы vs доллары:** одиночный `$...$` не считается формулой, если сразу после `$` идёт цифра (защита от `$100`, `$1,234`) — из-за этого формулы, начинающиеся с цифры (`$2x+1$`), не распознаются; для них нужен `\(...\)`. Крайний случай `$100$150` (два `$` впритык без пробела) теоретически может ложно сработать — на практике почти не встречается.
* **Таблицы и `white-space: nowrap`:** ячейки таблиц не переносят текст (нужно для надёжного горизонтального скролла на мобильных вместо сжатия колонок) — таблицы с длинными текстовыми описаниями в ячейках будут просто растягивать скролл, а не переноситься на несколько строк.
* **Сноски внутри код-блоков:** препроцессор `processFootnotes` не знает о границах `````-блоков, поэтому литеральный текст `[^1]` внутри примера кода тоже будет заменён. Актуально только если в примерах кода реально используется такой паттерн.
* **Графики — только декларативный конфиг:** JSON-конфиг в `chart`-блоке не поддерживает функции/колбэки Chart.js (кастомные тултипы, форматтеры осей и т.п.) — только то, что можно выразить статичными данными.
* **Дисклеймер (fence/инлайн) — без вложенного markdown:** текст выводится как есть, без обработки `**жирного**`, ссылок и т.д. Для форматирования внутри дисклеймера нужен сырой HTML-вариант.
* **`:has()`-селекторы** (чекбоксы, обёртка таблиц не затронута) требуют относительно свежих браузеров: Chrome/Edge/Safari — без проблем, Firefox — с версии 121+ (конец 2023). Для более старых браузеров чекбоксы отрендерятся, но список может не потерять нативный буллит.
* **Размер бандла:** `highlight.js` подключён полным пакетом (~190 языков), `chart.js/auto` — со всеми зарегистрированными типами графиков сразу. Если важен вес бандла — можно перейти на `highlight.js/lib/core` с ручной регистрацией нужных языков и на `chart.js` (без `/auto`) с ручной регистрацией только используемых типов графиков.

## Точки расширения

Если понадобится что-то ещё, добавляется по той же схеме — через `marked.use({ extensions: [...] })` в `marked-render.ts`:

* **Mermaid** — диаграммы-схемы прямо в постах (````mermaid` блоки), для флоучартов, архитектурных схем, последовательностей — то, что не выражается через данные Chart.js.
* **Номера строк в коде** — для постов, где обсуждается конкретная строка кода.
* **Diff-подсветка** — `highlight.js` уже поддерживает язык `diff` из коробки, нужно только проверить рендеринг.
* **Функции/колбэки в конфиге графиков** — если понадобится, например, кастомный формат тултипа, можно завести отдельный `chart-preset` (именованный пресет с уже готовым `options`, зашитым в код, а не в JSON поста) и ссылаться на него коротким ключом из markdown вместо полного конфига.
