# Все типы графиков Chart.js: какой выбрать и когда

Chart.js покрывает почти весь набор базовых визуализаций данных — от привычного столбчатого графика до полярных диаграмм и пузырьковых карт. В этой статье разберём каждый тип: что он показывает, когда уместен, а когда — нет, и как выглядит в реальном посте.

Все примеры ниже — рабочие `chart`-блоки, ровно такие же, какими можно пользоваться в любой статье блога.

---

## Bar — столбчатая диаграмма

Самый универсальный тип. Хорош для сравнения нескольких категорий между собой в один момент времени или в динамике по периодам.

```chart
{
  "type": "bar",
  "data": {
    "labels": ["Jan", "Feb", "Mar", "Apr", "May"],
    "datasets": [
      { "label": "Sales", "data": [12, 19, 8, 15, 22], "backgroundColor": "rgba(54, 162, 235, 0.7)" },
      { "label": "Costs", "data": [8, 11, 6, 10, 14], "backgroundColor": "rgba(255, 99, 132, 0.7)" }
    ]
  }
}
```

Когда брать: сравнение дискретных категорий — «продукт A против продукта B», «выручка по месяцам». Когда не брать: если категорий больше 10–15 — столбцы становятся нечитаемыми, лучше горизонтальный вариант или таблица.

**Горизонтальный вариант** (`options.indexAxis: "y"`) полезен, когда подписи категорий длинные и не помещаются под вертикальными столбцами:

```chart
{
  "type": "bar",
  "data": {
    "labels": ["Североамериканский рынок", "Европейский рынок", "Азиатско-Тихоокеанский регион"],
    "datasets": [{ "label": "Revenue, $M", "data": [420, 310, 275], "backgroundColor": "rgba(75, 192, 192, 0.7)" }]
  },
  "options": { "indexAxis": "y" }
}
```

**Stacked bar** — когда важна не только общая величина, но и её состав:

```chart
{
  "type": "bar",
  "data": {
    "labels": ["Q1", "Q2", "Q3", "Q4"],
    "datasets": [
      { "label": "Product A", "data": [10, 15, 12, 18], "backgroundColor": "#36a2eb" },
      { "label": "Product B", "data": [8, 9, 14, 10], "backgroundColor": "#ff6384" }
    ]
  },
  "options": {
    "scales": { "x": { "stacked": true }, "y": { "stacked": true } }
  }
}
```

## Line — линейный график

Показывает изменение значения во времени. Единственный тип, который стоит выбирать по умолчанию для временных рядов — глаз человека лучше всего считывает тренд именно по линии, а не по последовательности столбцов.

```chart
{
  "type": "line",
  "data": {
    "labels": ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"],
    "datasets": [{
      "label": "Visitors",
      "data": [120, 190, 150, 220, 180, 90, 60],
      "borderColor": "rgb(75, 192, 192)",
      "backgroundColor": "rgba(75, 192, 192, 0.15)",
      "fill": true,
      "tension": 0.3
    }]
  }
}
```

`tension` сглаживает линию между точками (0 — прямые отрезки, ближе к 1 — плавная кривая). `fill: true` закрашивает область под линией — полезно, когда важна не только динамика, но и накопленный «вес» показателя, но с несколькими датасетами сразу может превратиться в кашу — тогда `fill` лучше выключить.

Несколько линий на одном графике сравнивают динамику разных сущностей за один и тот же период:

```chart
{
  "type": "line",
  "data": {
    "labels": ["2020", "2021", "2022", "2023", "2024"],
    "datasets": [
      { "label": "Продукт A", "data": [30, 45, 42, 58, 71], "borderColor": "#36a2eb", "fill": false },
      { "label": "Продукт B", "data": [20, 25, 38, 40, 39], "borderColor": "#ff6384", "fill": false }
    ]
  }
}
```

## Pie / Doughnut — круговая и кольцевая диаграммы

Показывают долю каждой категории в целом. Работают хорошо только для небольшого числа сегментов (до 5–6) — дальше глаз перестаёт различать соседние по размеру куски.

```chart
{
  "type": "pie",
  "data": {
    "labels": ["Direct", "Search", "Social", "Referral"],
    "datasets": [{
      "data": [40, 30, 20, 10],
      "backgroundColor": ["#4285F4", "#FF7139", "#00C7B1", "#9E9E9E"]
    }]
  }
}
```

Doughnut — та же логика, но с вырезанной серединой. Часто выбирают чисто по эстетике, но вырезанный центр ещё и удобное место для общей суммы или подписи (уже средствами вёрстки поверх канваса, не через сам Chart.js):

```chart
{
  "type": "doughnut",
  "data": {
    "labels": ["Chrome", "Firefox", "Safari", "Other"],
    "datasets": [{
      "data": [55, 15, 20, 10],
      "backgroundColor": ["#4285F4", "#FF7139", "#00C7B1", "#9E9E9E"]
    }]
  }
}
```

Частая ошибка — пытаться уместить в pie/doughnut динамику по времени. Это не их задача: как только на графике не «доли одного целого в моменте», а тренд, нужен line или bar.

## Radar — радар (лепестковая диаграмма)

Сравнивает объект по нескольким параметрам одновременно — каждый параметр своя ось, расходящаяся из центра. Классика для сравнения игровых персонажей по характеристикам, но так же годится для сравнения продуктов, кандидатов, вариантов конфигурации по разным критериям.

```chart
{
  "type": "radar",
  "data": {
    "labels": ["Скорость", "Сила", "Ловкость", "Выносливость", "Навык"],
    "datasets": [
      { "label": "Игрок A", "data": [65, 59, 90, 81, 56], "borderColor": "#ff6384", "backgroundColor": "rgba(255, 99, 132, 0.2)" },
      { "label": "Игрок B", "data": [28, 48, 40, 19, 96], "borderColor": "#36a2eb", "backgroundColor": "rgba(54, 162, 235, 0.2)" }
    ]
  }
}
```

Работает хорошо для 2–3 датасетов и 4–8 осей. Больше двух сравниваемых сущностей — лепестки начинают перекрывать друг друга, читаемость падает.

## PolarArea — полярная область

Гибрид pie и radar: сектора одинаковой угловой ширины, но разной длины (в отличие от pie, где длина сектора всегда одна и та же, а меняется только угол). Показывает и долю, и величину одновременно.

```chart
{
  "type": "polarArea",
  "data": {
    "labels": ["Red", "Green", "Yellow", "Grey", "Blue"],
    "datasets": [{
      "data": [11, 16, 7, 3, 14],
      "backgroundColor": ["#ff6384", "#4bc0c0", "#ffce56", "#e7e9ed", "#36a2eb"]
    }]
  }
}
```

Используется реже остальных — визуально эффектно, но новому читателю не всегда очевидно, как её читать. Хорошо заходит в статьях, где сам факт «необычной формы» работает как акцент, а не как основной источник точных чисел.

## Scatter — точечная диаграмма

Показывает связь между двумя числовыми переменными: каждая точка — отдельное наблюдение с координатами `x` и `y`. Основной инструмент для поиска корреляций и выбросов в данных.

```chart
{
  "type": "scatter",
  "data": {
    "datasets": [{
      "label": "Наблюдения",
      "data": [
        { "x": -10, "y": 0 }, { "x": 0, "y": 10 }, { "x": 10, "y": 5 },
        { "x": 20, "y": 15 }, { "x": 5, "y": -5 }, { "x": 15, "y": 8 }
      ],
      "backgroundColor": "#e91e63"
    }]
  },
  "options": {
    "scales": { "x": { "type": "linear", "position": "bottom" } }
  }
}
```

Важно: ось `x` нужно явно задать как `"type": "linear"` — по умолчанию Chart.js трактует ось как категориальную, и точки лягут не туда. Для line/bar это не нужно, только для scatter/bubble.

## Bubble — пузырьковая диаграмма

То же, что scatter, плюс третье измерение — размер точки (`r`). Удобно, когда нужно показать не два, а три показателя разом: например, x — цена, y — рейтинг, размер пузыря — объём продаж.

```chart
{
  "type": "bubble",
  "data": {
    "datasets": [{
      "label": "Продукты",
      "data": [
        { "x": 20, "y": 30, "r": 15 },
        { "x": 40, "y": 10, "r": 25 },
        { "x": 15, "y": 50, "r": 8 },
        { "x": 35, "y": 35, "r": 18 }
      ],
      "backgroundColor": "rgba(255, 159, 64, 0.6)"
    }]
  }
}
```

Главный риск — переусложнить. Три измерения на одном графике читаются заметно тяжелее, чем два, так что bubble стоит подписывать явно и не перегружать множеством точек одновременно.

## Сводная таблица: что когда выбирать

| Тип | Показывает | Макс. категорий/датасетов |
| --- | --- | --- |
| Bar | Сравнение категорий | до 10–15 категорий |
| Line | Динамика во времени | 2–4 линии без потери читаемости |
| Pie / Doughnut | Доли одного целого | до 5–6 сегментов |
| Radar | Сравнение по нескольким критериям | 2–3 датасета, 4–8 осей |
| PolarArea | Доля + величина | до 6–8 секторов |
| Scatter | Связь двух переменных | без строгого лимита, но нужна плотность данных |
| Bubble | Связь трёх переменных | 10–20 точек, дальше плохо читается |

## Как оформить на странице

Любой из графиков выше можно вставить с направлением обтекания, чтобы он не растягивался на всю ширину поста, а шёл рядом с текстом:

```chart:right
{
  "type": "line",
  "data": {
    "labels": ["Jan", "Feb", "Mar", "Apr"],
    "datasets": [{ "label": "Trend", "data": [10, 25, 18, 30], "borderColor": "#0b7a30", "fill": false }]
  }
}
```

Так график из этого раздела обтекается текстом справа — обратите внимание, весь этот абзац идёт слева от него без каких-либо ручных обёрток, просто за счёт модификатора `:right` в языке code fence.

Разбор всех модификаторов (`:left`, `:right`, `:float`, `:full`) и общего синтаксиса `chart`-блока — в справочнике синтаксиса для авторов.
